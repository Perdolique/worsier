# Worsier

Worsier is a focused JavaScript, TypeScript, JSX, and TSX formatter powered by Rust. Each rule is independently configurable, and source outside enabled rules is preserved instead of being reprinted.

Node.js 24.0.0 or newer is required.

## Installation

```sh
pnpm add -D worsier
```

Check a project without changing files:

```sh
pnpm exec worsier --check .
```

Format it in place:

```sh
pnpm exec worsier --write .
```

## CLI

| Command | Purpose |
| --- | --- |
| `worsier file.ts` | Format one file and print the result |
| `worsier --check PATH...` | Check files or directories without writing |
| `worsier --write PATH...` | Format files or directories in place |
| `worsier --stdin-filepath file.ts` | Format stdin using the supplied file type |
| `worsier --config path/to/worsier.jsonc` | Use one explicit configuration |
| `worsier --init` | Create a complete `worsier.jsonc` |
| `worsier --threads 4` | Set the number of formatting workers |
| `worsier --no-verify` | Disable AST verification for one invocation |

Directories and multiple files require either `--check` or `--write`. Directory discovery skips `.git`, `node_modules`, and Wrangler's generated `worker-configuration.d.ts`. An explicitly passed file is still processed even when it matches an ignore rule.

## Configuration

A configuration file is optional. For every input, the CLI searches upward for the nearest `worsier.jsonc`, stopping at the Git or filesystem root. An invalid discovered or explicit file is an error; Worsier does not silently fall back to defaults.

This is the complete default configuration generated by `worsier --init`:

```jsonc
{
  "$schema": "./node_modules/worsier/configuration_schema.json",
  "lineWidth": 120,
  "verifyAst": true,
  "rules": {
    "importLayout": true,
    "interfaceLayout": 0,
    "statementSpacing": {
      "imports": "separate",
      "typeAliases": "separate",
      "variableDeclarations": "separate"
    },
    "semicolons": {
      "statements": "asNeeded",
      "classMembers": "asNeeded",
      "typeMembers": "asNeeded"
    },
    "trailingCommas": "never"
  },
  "ignorePatterns": []
}
```

`ignorePatterns` accepts glob patterns. Unknown keys and invalid values are configuration errors.

## Formatting rules

| Rule | Default | What it controls |
| --- | --- | --- |
| `rules.importLayout` | `true` | Layout inside static imports |
| `rules.interfaceLayout` | `0` | TypeScript interface expansion threshold |
| `rules.statementSpacing.imports` | `"separate"` | Boundaries around static imports |
| `rules.statementSpacing.typeAliases` | `"separate"` | Boundaries around direct type aliases |
| `rules.statementSpacing.variableDeclarations` | `"separate"` | Boundaries around direct runtime variables |
| `rules.semicolons.statements` | `"asNeeded"` | Runtime and TypeScript statement endings |
| `rules.semicolons.classMembers` | `"asNeeded"` | Class field and declaration endings |
| `rules.semicolons.typeMembers` | `"asNeeded"` | Interface and object-type member endings |
| `rules.trailingCommas` | `"never"` | Optional trailing commas in supported lists |

### Imports

`importLayout` formats only static imports. Named specifiers stay on one line while the complete import fits `lineWidth`; otherwise each specifier is placed on its own line. Specifier order, aliases, `type` modifiers, quotes, attributes, and comments are preserved. Default-only, namespace, side-effect, and dynamic imports are not expanded.

```ts
import {
  type Config,
  format
} from 'worsier'
```

Set `importLayout` to `false` to preserve the existing import layout. The trailing-comma and statement-semicolon rules remain independent; set `rules.trailingCommas` and `rules.semicolons.statements` to `"off"` as well when the complete import text must remain unchanged.

### Interfaces

`interfaceLayout` is either `"off"` or a member threshold from `0` through `4294967295`. An interface expands only when its direct member count is greater than the threshold, so the default `0` expands every nonempty interface.

```ts
interface Example {
  value: string
  run(): void
}
```

Member text, order, comments, and nested layout are preserved. Separators remain controlled independently by `rules.semicolons.typeMembers`. Members covered by a preceding `// @ts-ignore` or `// @ts-expect-error` remain on the same physical line so formatting does not change the directive's scope. Object type aliases are not handled by this rule.

### Statement spacing

Each spacing rule accepts one of three modes:

| Mode | Result |
| --- | --- |
| `"separate"` | Keep adjacent single-line statements of the same category together; add a blank line around multiline statements and other code |
| `"compact"` | Use exactly one line break |
| `"off"` | Do not impose a boundary |

When two configured categories meet, the stricter boundary wins. Spacing can also unfold an inline statement list, using two-space indentation.

Type-alias spacing applies to direct, unexported `type` declarations. Variable spacing applies to direct runtime `const`, `let`, and `var` declarations. Exported or ambient declarations and variables in `for` headers are left outside those rules.

### Semicolons

Each semicolon group accepts `"always"`, `"asNeeded"`, or `"off"`. `"asNeeded"` removes optional semicolons and inserts a leading guard when the next statement or computed class member could otherwise be joined by automatic semicolon insertion:

```ts
const values = load()
;[first, second].forEach(use)
```

Required semicolons, `for` header separators, standalone empty statements, and commas between TypeScript type members are preserved. `"off"` leaves the selected group unchanged.

### Trailing commas

`trailingCommas` accepts `"always"`, `"never"`, or `"off"`:

- `"always"` adds a comma to eligible multiline lists and removes it from single-line lists.
- `"never"` removes optional trailing commas.
- `"off"` preserves them.

The rule covers object and array literals, destructuring, named static imports and exports, parameters, arguments, tuples, enums, and type parameters. It preserves commas that are required by syntax or semantics, including sparse-array elisions, and never adds a comma after a rest item. Dynamic `import()` arguments and TypeScript type arguments are not changed.

## Programmatic API

```js
import { format } from 'worsier'

const output = await format(
  'example.ts',
  "import{answer,type Value}from'pkg'",
  { rules: { trailingCommas: 'always' } }
)
```

`format(fileName, sourceText, config?)` returns a promise with the formatted source. The optional `FormatConfig` argument uses the same defaults as the CLI, but the API does not discover configuration files.

## Guarantees and scope

- Worsier preserves source outside the imports, interfaces, semicolons, trailing commas, and statement boundaries controlled by enabled rules.
- Rewritten text keeps the source's LF or CRLF line endings. UTF-8 BOM and final-newline presence are preserved.
- `verifyAst: true` reparses the result and rejects changes that do not match the input Oxc AST.
- Formatting is idempotent: formatting an already formatted file produces no further changes.
- Set every rule to `"off"` or `false` to make formatting return the source unchanged.

## Performance benchmarks

Benchmarks are report-only until release measurements establish a stable threshold. Tagged releases run the complete Rust Criterion suite and Node.js cold-start benchmark and include the report in the GitHub release.

After building and testing the workspace, run them locally with:

```sh
vp run check
cargo bench -p worsier-formatter --features benchmarking --bench formatter -- --noplot
vp run benchmark:node
```

The suite compares parsing, AST verification, full formatting, semicolons disabled, and trailing commas disabled across small, 50 KB, and 1 MB import-heavy inputs. The Node.js benchmark measures API and CLI cold starts in fresh processes.

## Alternatives

[Prettier](https://prettier.io/docs/) is a mature opinionated formatter that prints the complete source. [Oxfmt](https://oxc.rs/docs/guide/usage/formatter.html) is a fast, Prettier-compatible formatter with broader language and formatting coverage. Worsier instead focuses on independent source-rewrite rules and preserving text outside those rules.
